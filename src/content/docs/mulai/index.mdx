## Siapkan folder kerja

Kita akan menjawabnya lewat satu file `toko.dim`. Siapkan Node.js 24 dan Bun, lalu jalankan perintah berikut di terminal.

```sh
mkdir dim-checkout
cd dim-checkout
bun add https://github.com/dim-language/dim-sdk/releases/download/v0.2.0/dim-sdk-0.2.0.tgz
```

Simpan kode berikut sebagai `check.mjs` di folder itu. Skrip ini membaca file yang kamu berikan, menjalankan compiler, lalu mencetak jumlah elemen dan relasinya.

```js contoh-tutorial="check.mjs"
```

## 1. Orang dan sistem

Buat file `toko.dim` dan isi dengan model berikut.

```dim contoh-tutorial="sistem.dim"
```

Setiap elemen punya jenis (`person` atau `system`), ID yang dipakai dalam kode, dan nama yang tampil di peta. Panah `pembeli -> toko` menunjukkan bahwa pembeli yang memulai interaksi. Deklarasi tanpa blok diakhiri dengan `;`.

```bash
node check.mjs toko.dim
```

```text contoh-tutorial="sistem"
```

Dua elemen dan satu relasi sudah cukup untuk menggambarkan siapa yang memakai toko online.

## 2. Isi sistemnya

Ganti isi `toko.dim` dengan model ini. Ketiga `container` berada di dalam `toko` dan dirujuk dengan path seperti `toko.web`.

```dim contoh-tutorial="container.dim"
```

<BrianNote scene="review">Tutup dulu jawabannya. Dari sudut pandang Web, mana yang dikirim dan mana yang diterima? Cari dua kata setelah `data` di relasi POST.</BrianNote>

- `ui` menandai Web sebagai antarmuka yang dipakai pembeli. `shape database` memberi Postgres bentuk database di peta.
- Web mengirim `Pesanan` ke API dengan `data push` dan menerima `IdPesanan` dengan `data pull`. Pada `op write`, `push` sudah menjadi arah bawaan.
- Saat `toko` tertutup di peta, relasi `pembeli -> toko.web` tampil sebagai `pembeli → toko`.

```bash
node check.mjs toko.dim
```

```text contoh-tutorial="container"
```

## 3. Turun ke kode

Ganti lagi isi `toko.dim`. Kali ini `api` berisi komponen `pesanan` yang punya fungsi `simpan_pesanan()`. Gunakan path fungsi itu sebagai asal relasi `INSERT pesanan`.

```dim contoh-tutorial="kode.dim" ins={10-12} ins="toko.api.pesanan.simpan"
```

```bash
node check.mjs toko.dim
```

```text contoh-tutorial="kode"
```

Jumlah relasinya tetap tiga karena relasi `INSERT pesanan` sekarang dimulai dari fungsi. Perbesar peta untuk mengikuti panah `API → Postgres` sampai sumbernya terlihat sebagai `simpan_pesanan() → Postgres`.

Di peta berikut, perbesar sampai Web dan API terlihat. Pilih relasi POST dan baca dua entri datanya. Web mengirim `Pesanan` dan menerima `IdPesanan`. Perkecil sampai toko tertutup. Panah POST menghilang karena kedua ujungnya ada di dalam toko.

## 4. Latihan memperbaiki error

Di baris `POST /pesanan`, ubah `data push "Pesanan"` menjadi `data "Pesanan"`, lalu cek lagi.

```bash
node check.mjs toko.dim
```

Cari baris ini pada output skrip.

```text contoh-tutorial="tanpaArah"
```

`op call` bisa mengirim permintaan dan menerima respons, jadi tentukan arah setiap `data`. Tambahkan kembali `push`, lalu jalankan `node check.mjs toko.dim` sampai ringkasan `ok` dari langkah ketiga muncul lagi.

## Coba dengan satu PR

<BrianNote scene="your-turn">Ambil satu perubahan yang lagi lo review. Siapa yang mulai interaksi, dan apa yang dia harapkan balik?</BrianNote>

Salin `toko.dim` ke `pr.dim`. Ganti nama tampilan Web dan API sesuai sistemmu, lalu ubah label POST serta tipe request dan respons sesuai diff PR. Pertahankan ID agar path tetap cocok. Jalankan `node check.mjs pr.dim`. Setelah muncul `ok`, minta reviewer membaca relasi itu dan menyebutkan hasil yang diterima pemanggil. Cocokkan jawabannya dengan kode PR.

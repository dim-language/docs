Di rapat desain, tim Web menunjukkan layar struk. Setelah pembeli menekan Pesan, layar itu akan menampilkan rincian pesanan yang baru tersimpan. Tim API menyanggupi dua hal. API akan menulis pesanan ke Postgres, lalu mengembalikan pesanan lengkap ke Web. Dido membuka peta kemarin. Panah dari pembeli ke toko belum cukup untuk menjelaskan dari mana isi struk berasal.

## Buka kotak toko

Ganti isi `toko.dim` dari bab pertama dengan rancangan tim. Beri setiap container perannya: `app` untuk Web, `service` untuk API, dan `database` untuk Postgres. Tim API menyebut isi pesanannya, jadi Dido mencatatnya sebagai `record` di component Pesanan, dan panah merujuknya lewat path. Pindahkan ujung panah Belanja ke `toko.web`.

```dim contoh-tutorial="checkout.dim"
```

```sh
node check.mjs toko.dim
```

```text contoh-tutorial="checkout"
```

Ikuti panah POST dari sisi Web. `push` membawa pesanan ke API. Setelah penulisan ke database, `pull` membawa pesanan lengkap kembali ke layar struk. Dido meminta kedua tim membaca panah itu sebelum mereka mulai mengerjakan bagiannya.

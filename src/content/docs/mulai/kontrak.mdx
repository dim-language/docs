Saat mencoba prototipe di ponsel, tim produk memutuskan untuk menampilkan nomor pesanan saja. Tim API pun memangkas respons checkout. Dido menemukan satu baris di model yang sekarang sudah basi.

<DidoNote scene="order-id">Kalau yang balik cuma ID, bagian mana dari panah POST yang mesti gue ubah?</DidoNote>

Di `toko.dim`, tambahkan tipe untuk nomor pesanan di component Pesanan, lalu ubah bagian `pull` di relasi POST saja. Web masih mengirim pesanan lengkap dan API masih menyimpannya.

```diff
+      alias idPesanan "IdPesanan" {
+        description "Nomor pesanan yang tampil di layar konfirmasi.";
+        type uuid;
+      }
```

```diff
-  data pull toko.api.pesanan.dataPesanan;
+  data pull toko.api.pesanan.idPesanan;
```

```sh
node check.mjs toko.dim
```

## Periksa arah saat review

Jumlah panah tetap sama. Untuk melihat apa yang diperiksa compiler, coba hapus kata `push` dari request dan jalankan lagi perintah tadi.

```text contoh-tutorial="tanpaArah"
```

Setiap baris `data` perlu arah. Kembalikan `push`, jalankan cek sampai muncul `ok`, lalu cocokkan `data pull toko.api.pesanan.idPesanan` dengan respons yang disepakati tim API. Tipe yang dijanjikan ke Web tetap perlu diperiksa saat review.

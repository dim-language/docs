Saat mencoba prototipe di ponsel, tim produk memutuskan untuk menampilkan nomor pesanan saja. Tim API pun memangkas respons checkout. Dido menemukan satu baris di model yang sekarang sudah basi.

<DidoNote scene="order-id">Kalau yang balik cuma ID, bagian mana dari panah POST yang mesti gue ubah?</DidoNote>

Di `shop.dim`, tambahkan tipe untuk nomor pesanan di component Orders, lalu ubah bagian `pull` di relasi POST saja. Web masih mengirim pesanan lengkap dan API masih menyimpannya.

```diff
+      alias orderId "OrderId" {
+        description "The order number shown on the confirmation screen.";
+        type uuid;
+      }
```

```diff
-  data pull shop.api.orders.order;
+  data pull shop.api.orders.orderId;
```

```sh
node check.mjs shop.dim
```

## Periksa arah saat review

Jumlah panah tetap sama. Untuk melihat apa yang diperiksa compiler, coba hapus kata `push` dari request dan jalankan lagi perintah tadi.

```text contoh-tutorial="tanpaArah"
```

Setiap baris `data` perlu arah. Kembalikan `push`, jalankan cek sampai muncul `ok`, lalu cocokkan `data pull shop.api.orders.orderId` dengan respons yang disepakati tim API. Tipe yang dijanjikan ke Web tetap perlu diperiksa saat review.

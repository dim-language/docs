---
title: Usage guides
description: Choose a guide for the change you want to make.
---

Choose the task in front of you. If you don't have a `.dim` file yet, start with [your first model](/en/mulai/).

- [Map an existing system](/en/menulis/memodelkan/) — Start with one user, one action, and the service that responds.
- [Set up dim.config](/en/menulis/konfigurasi/) — Declare technologies, tags, and styles once for the whole project.
- [Choose elements and properties](/en/menulis/elemen/) — Set the system boundary, container roles, and their paradigms.
- [Connect two elements](/en/menulis/relasi/) — Give the relation an id, pick an `op`, and write the source and target paths.
- [Separate the caller from the data direction](/en/konsep/aliran-data/) — Record a request and its response on one arrow.
- [Document an endpoint](/en/konsep/endpoint/) — Write an HTTP, gRPC, GraphQL, or event contract, then let callers use it.
- [Record a function contract](/en/konsep/level-kode/) — Write types, parameters, results, and errors in the paradigm of the code.
- [Trace a flow](/en/konsep/alur/) — Follow checkout from the click to the saved order, including the failure path.
- [Split a model into several files](/en/konsep/komposisi/) — Separate two teams' parts and write a *to-be* model.
- [Map where software runs](/en/konsep/deployment/) — Place containers on clusters and regions per environment.
- [Read arrows as the zoom changes](/en/konsep/peta-zoom/) — Find the function that writes to the database.
- [Add a map to an Astro page](/en/ekosistem/peta-web/) — Share an interactive model with reviewers.

## Follow checkout from system to code

In this online shop, `OrderRepository.save()` saves an order to Postgres. dim uses that relation to draw **API → Postgres** when you look inside the shop. At the system level, the relation stays inside the **Online Shop** box.

[How dim derives arrows at each zoom level](/en/konsep/peta-zoom/)

</div>
<div>

```dim title="shop.dim"
insert_order: api.orders.repo.save -> db "INSERT orders" {
  op write;
  data "Order";
}
```

## Describe the request and response

The checkout button starts the call. The Web App sends a `CheckoutRequest` with `data push` and receives an `OrderId` from the API with `data pull`. The **Web App → API** arrow records both.

[How to describe interactions and data flow](/en/konsep/aliran-data/)

</div>
<div>

```dim title="shop.dim"
checkout_post: web.checkout.button -> api.checkout.route "POST /checkout" {
  op call;
  tech "HTTPS/JSON";
  data push "CheckoutRequest";
  data pull "OrderId";
}
```

</div>

## Check the model locally and in CI

Use `compileProject` to validate the model and its imports. For example, if you drop `push` from `data push "CheckoutRequest"`, the compiler reports `E035` on the line that needs a direction. You can run the same check in CI.
